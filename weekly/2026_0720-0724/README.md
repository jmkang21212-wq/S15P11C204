- 핵심 기능의 MVP 범위와 우선순위 확정

## 주요 진행 내용

1. 서비스명을 **LAIVE**로 정하고, “혼자여도, 혼자가 아닌 방송”이라는 핵심 메시지를 수립했습니다.
2. 방송 중에는 위험 발언·약속·채팅 여론·반복 질문을 실시간으로 브리핑하고, 방송 후에는 리포트·하이라이트·클립·포트폴리오를 생성하는 서비스 흐름을 구체화했습니다.
3. 기능 요구사항을 MoSCoW 방식으로 분류하고 위험 발언 감지, 실시간 채팅 분석, 방송 리포트, 하이라이트 탐지, 성장 리포트와 포트폴리오를 중심으로 MVP 범위를 정리했습니다.
4. Electron·React 클라이언트, Spring Boot API 서버, FastAPI AI 서버, PostgreSQL·Redis·S3 호환 스토리지를 연결하는 시스템 구조를 설계했습니다.
5. 인증, 플랫폼 연동, 일정, 대시보드, 방송 세션, WebSocket 브리핑, 약속, 리포트, 하이라이트, 성장 목표, 포트폴리오 및 내부 AI 분석 API를 상세화했습니다.
6. 스트리머와 방송 세션을 중심으로 채팅·STT·위험 발언·약속·리포트·하이라이트·포트폴리오가 연결되는 ERD를 작성하고 API와의 매핑을 점검했습니다.
7. 45장 분량의 기획 발표 자료를 완성하고 발표 흐름, 차별성, 적용 기술, 데이터 표현 및 시각 디자인에 대한 피드백을 받았습니다.

## 기획 발표 및 피드백

- 전체 발표 흐름과 가독성은 긍정적으로 평가받았으며, 구조를 바꾸기보다 세부 표현을 다듬고 발표의 **킥**을 강화하는 방향으로 정리했습니다.
- 신규 스트리머 포기율과 수익 통계는 메시지를 분리하고, 부정 프레임에 맞는 색상·아이콘·문구로 수정할 필요가 있습니다.
- 시장 성장 데이터는 **CAGR 23%**를 중심으로 강조하고 단위를 통일하며, 원본 데이터를 사용한 PowerPoint 네이티브 그래프로 다시 구성하기로 했습니다.
- 기획자·매니저·편집자·마케터 등 역할 용어를 통일하고, 여러 역할이 LAIVE 하나로 합쳐지는 메시지를 강화하기로 했습니다.
- 유튜브·SOOP·치지직의 지원 기능과 LAIVE를 비교하는 표를 추가하여 크로스 플랫폼 차별성을 명확히 할 필요가 있습니다.
- 이벤트 기반 LLM 호출과 **z-score 하이라이트 탐지 로직**을 상세히 설명하는 기술 장표를 보강할 필요가 있습니다.
- 상단 네이비 바, 박스 크기, 자간, 페이지 번호, 작은 텍스트와 이미지 화질을 정리하고 고도화 방안은 한 장에 하나씩 제시하기로 했습니다.
- 라이브 데모, 3D AI 매니저 캐릭터, SSAFY 방송 활용 제안 중 발표의 와우 포인트가 될 요소를 선정해야 합니다.
