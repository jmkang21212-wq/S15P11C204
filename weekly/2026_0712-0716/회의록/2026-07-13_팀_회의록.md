    ## 💬 회의 내용
    
    ### 1. 보드게임 매니저
    
    - 주말 조사 공유 — 턴 감지 방식
        - 객체 탐지(손 객체 추적) 대신 **움직임(변화) 감지**: 손 진입 시 판정 보류 → 손이 보드에서 빠지고 일정 시간 무변화일 때 진입 전·후 보드 상태를 비교해 무엇이 움직였는지 파악
        - 턴 종료 확정은 영상만으로 불충분(착수 후 무르기 가능) → **음성 인식 · 화면 버튼 · 토큰 조작 등 2중 확인 장치** 병행
        - MVP 게임: 변화가 시각적으로 명확한 단순 게임 — **오델로** 후보
    - WebRTC 정합성 논쟁 (미합의)
        - "실물 보드 + 고정 캠 구조에는 굳이 필요 없다"는 의견 vs "AI 서버를 하나의 피어로 두고 여러 룸의 캠이 연결되는 구조로 쓸 수 있고, 영상 전송에는 일반 서버 통신보다 RTC가 빠르다"는 질의
        - "RTC는 핸드셰이킹 개념이고 실제 전송은 내부적으로 다르다"는 의견도 제기 (결론 없이 지나감)
        - 단방향 사용 반대 의견: 이전 프로젝트 피드백 경험상 기술 선택 이유가 명확해야 하며, 양방향 통신용 기술을 단방향으로 쓰면 지적받을 것 → 기술 특징을 명확히 살리는 방향 필요
        - 반론: 목표에 맞으면 가볍게 "한 스푼"만 들어가도 기준 통과 가능, 질문받으면 설득 가능
    - 영상 분석 리스크: 아무리 잘 만들어도 오류는 발생하고, 오류 시 사용자 경험 급락 우려
    - 방향: 실물 보드 영상 분석 대신 **온라인(웹) 보드게임 플랫폼 + 화상 + AI** 방향으로 전환 검토
    
    ### 2. 방송(스트리머) 매니저
    
    - 치지직 공식 API: 본인 방송 채팅 제어 수준 — 라이브 채팅 전체 수집 API 부재
    - *비공식 API(깃허브 커뮤니티 제작)**로 채팅 데이터 수집 가능 → 활용 검토
    - 플랫폼 조사: 치지직에서 채팅 작성자 ID·닉네임, 후원·구독 정보 등 핵심 기능 데이터 확보 가능 / SOOP은 다중 스트리머 연결 시 별도 제휴 승인 필요 → **치지직 단독 우선 구현**이 현실적
    - 연결 방식: 토큰 기반 인증(액세스·리프레시 토큰)
    - RTC 접점 문제: "채팅 API만 읽어 관리하는 서비스에 RTC가 왜 필요한가" → 웹 스트리밍 플랫폼 직접 구현안, 매니저↔스트리머 실시간 소통안이 제시됐으나 "웹 스트리밍을 만들어도 결국 RTC는 안 쓰게 될 것"이라는 반론
    - 시연 전략: 채팅 로그를 사전 확보해 재생하는 방식 가능
    
    ### 3. 고객 상담 → 웹 기반 보이는 ARS
    
    - 상담원 보조는 기존 솔루션 다수(대형 클라우드 포함)로 차별화 곤란, 상담원·고객 병행 제공도 유사 사례 존재하는 것으로 파악
    - 고객 사이드가 상대적 공백(단순 에이전트 제공 수준) → **사용자 쪽으로 프레임 이동**
    - 보이는 ARS: 음성으로만 하던 안내를 화면(문자·카테고리·버튼)과 동시 제공, 입력도 번호·발화 대신 터치·채팅으로 — 팀 내 실사용 경험이 긍정적
    - 사회공헌 확장: 보이는 ARS 접근이 어려운 **노약자·장애인 대상 기능**을 추가해 사회공헌성(수상 기준) 확보
    - 요건: 상담 대상 도메인(가상 쇼핑몰 등 화상 서비스) 필요, AI 접목 지점 추가 구체화 필요
    
    ### 4. AI 면접 — 폐기
    
    - 차별성 부족("알아볼수록 너무 뻔함")으로 메인 후보에서 제외, 차선책으로만 유지
    
    ### 5. 신규 아이디어
    
    - **보드게임 훈수**: 바둑계에서 AI 훈수가 사실상 표준(기사 평가 지표 = AI 일치도, 중계에서도 AI 추천 수 표시) → 웹 구현 보드게임 + 해당 게임을 학습한 AI의 수 추천·코칭. 보드게임 **규칙 자체에는 저작권 없음**(명칭·이미지에만 존재, 리네이밍 사례: 할리갈리 → 유사 명칭 서비스). 구현은 React로도 가능(보드게임은 게임 엔진 불필수), Phaser 등 웹 엔진도 후보
    - **테이블탑 시뮬레이터형**: 게임을 시스템으로 만들지 않고 비품(말·카드 등)만 구현, 진행은 수동 → 다양성 확보 가능. 수동인 부분(사회·점수 계산)을 AI로 보완하고, 원격 게임화하면 RTC 요건도 자연 충족된다는 제안
    - **AI 자소서·공고 추천 플랫폼**: 내 정보·깃허브를 직접 입력·저장 → 근거 기반 자소서 보조 + 채용 공고 추천. RTC는 기업↔취준생 실시간 채팅으로 최소 적용. 단, **타 팀이 유사 주제 진행 중**으로 파악 → 비교 리스크(발표 순서 인접 시 불리했던 과거 경험 공유됨)
    - **프로젝트 협업 AI 도구**: ERD·인프라 설계 등을 팀원과 함께 만들 때 요구사항·공식 문서(AWS 문서 등) 기반 실시간 피드백. 해외 유사 서비스 존재(국내 미확인), 아이디어 수준
