# 전체 추천 기술 스택 정리

| 영역 | 추천 기술 | 적용 기능 | 추천 이유 | 우선순위 |
| --- | --- | --- | --- | --- |
| 프론트엔드 | **React + TypeScript** | 대시보드, 매니저 브리핑, 프로필, 합방 UI | 실시간 상태 관리와 대시보드 생태계가 풍부하고, OBS Browser Source용 웹 화면도 함께 개발 가능 | 필수 |
| 프론트 상태 관리 | **TanStack Query + Zustand** | 서버 데이터, 친구 상태, 대기열, 알림 | 서버 데이터와 UI 상태를 분리해 관리하기 쉽고 구현 부담이 비교적 낮음 | 필수 |
| UI | **Tailwind CSS** | 전체 화면, OBS 오버레이 | 빠른 UI 제작과 반응형 화면 구현에 적합 | 필수 |
| 차트 | **Apache ECharts** | 시청자 추이, 감정 히트맵, 성과 비교 | 시계열 차트와 히트맵 표현 기능이 강함 | 필수 |
| 메인 백엔드 | **Java + Spring Boot** | 회원, 프로필, 일정, 매칭, 비즈니스 로직 | 인증·DB·배치·WebSocket을 한 생태계에서 구성할 수 있고 팀의 Java 역량을 활용 가능 | 필수 |
| 인증·인가 | **Spring Security + JWT/OAuth2** | 스트리머·기업 계정, 권한 분리 | 스트리머·기업·관리자 역할별 접근 제어와 외부 로그인 연동에 적합 | 필수 |
| 실시간 데이터 | **Spring WebSocket + STOMP** | AI 브리핑, 대기열, 상태판, 알림, 통계 갱신 | 텍스트·이벤트를 지속 연결로 즉시 전달할 수 있고 Spring Security와 연계 가능 | 필수 |
| AI 서버 | **Python + FastAPI** | STT, LLM 호출, 분석 모델, 추천 | Python AI 라이브러리를 활용하기 쉽고 Spring 서버와 역할을 분리할 수 있음 | 필수 |
| 관계형 DB | **PostgreSQL** | 사용자, 방송, 통계, 일정, 협업 이력 | 관계형 데이터와 JSON 형태의 분석 결과를 함께 관리하기 편리 | 필수 |
| 캐시·실시간 상태 | **Redis** | 시참 대기열, 친구 상태, 세션, 임시 분석 결과 | 빠른 읽기·쓰기와 TTL을 지원해 방송 중 휘발성 데이터 관리에 적합 | 필수 |
| 객체 저장소 | **AWS S3 또는 MinIO** | 클립, 썸네일, 리포트 파일, 미디어 킷 | 대용량 영상·이미지를 DB와 분리해 저장 가능 | 필수 |
| 방송 연동 | **OBS Studio** | 화면·오디오 입력, 송출, 클립, 오버레이 | 기존 스트리머 환경을 유지하면서 AI 서비스와 연결 가능 | 필수 |
| OBS 제어 | **obs-websocket** | 방송 시작·종료, 장면 변경, Replay Buffer 저장 | OBS 기능을 외부 서비스에서 이벤트 기반으로 제어할 수 있음. obs-websocket은 OBS 기능에 접근하는 RPC 프로토콜을 제공함 ([GitHub](https://github.com/obsproject/obs-websocket/blob/master/docs/generated/protocol.md?utm_source=chatgpt.com)) | 필수 |
| OBS 화면 표시 | **OBS Browser Source** | AI 캐릭터, 시참 목록, 경고, 합방 정보 | React로 만든 웹 UI를 방송 화면 위에 오버레이로 표시 가능 | 필수 |
| STT | **faster-whisper** | 발언 모니터링, 약속 추적, 방송 요약 | Whisper 계열 모델을 비교적 빠르게 로컬 추론할 수 있어 개인정보와 API 비용 관리에 유리 | 필수 |
| LLM | **외부 LLM API** | 채팅 요약, 콘텐츠 제안, 리포트, 브리핑 문구 | 초기 MVP에서 자체 모델 운영보다 개발 속도와 품질 확보에 유리 | 필수 |
| 영상 처리 | **FFmpeg** | 클립 자르기, 쇼츠 변환, 오디오 추출 | 영상 구간 추출·인코딩·세로 영상 변환의 사실상 표준 도구 | 필수 |
| 배치 처리 | **Spring Batch + Scheduler** | 일간·주간 리포트, 성장 지표 집계 | 재시도와 작업 단위 관리가 필요한 정기 통계 처리에 적합 | 필수 |
| 합방 미디어 | **WebRTC + LiveKit** | 화상·음성 룸, 화면 공유, 버튜버 합방 | LiveKit은 WebRTC 기반 SFU로 다자간 실시간 미디어를 중계하며 확장 구조를 제공함 ([LiveKit 문서](https://docs.livekit.io/reference/internals/livekit-sfu/?utm_source=chatgpt.com)) | 2단계 |
| 메시지 브로커 | **Kafka** | 대규모 채팅·분석 이벤트 파이프라인 | 채팅 수집, 감정 분석, 저장 등 여러 소비자가 동일 이벤트를 처리할 때 유리 | 확장 |
| 벡터 검색 | **pgvector** | 방송 이력 검색, 근거 기반 추천, RAG | PostgreSQL 안에서 관계형 데이터와 임베딩을 함께 관리 가능 | 확장 |
| 검색 엔진 | **OpenSearch/Elasticsearch** | 기업의 스트리머 검색 | 조건·키워드·랭킹이 복잡해질 때 강력하지만 MVP에는 과함 | 확장 |
| 배포 | **Docker + Docker Compose** | 전체 서비스 배포 | Spring, FastAPI, Redis, DB를 동일 환경으로 구성하고 재현하기 쉬움 | 필수 |
| CI/CD | **GitLab CI 또는 GitHub Actions** | 테스트·배포 자동화 | 팀 프로젝트에서 빌드와 배포 실수를 줄일 수 있음 | 권장 |
| 모니터링 | **Prometheus + Grafana** | 지연 시간, 오류율, STT 처리 속도 | 실시간 서비스의 병목과 장애 원인을 수치로 확인 가능 | 권장 |
| 로그 | **Loki 또는 ELK/OpenSearch** | 서비스·AI 분석 로그 | 방송별 이벤트 흐름과 오류를 추적하기 좋음 | 권장 |
