# 개인 사전 설정 화면 연동 규격

> 대상: **프론트엔드**
> 서버 설계·구현 배경은 [RISK_POLICY_SPEC.md](RISK_POLICY_SPEC.md)에 따로 있다.
> 음성 WebSocket 규격은 [FRONTEND_API.md](FRONTEND_API.md)이며 **이번 변경으로 바뀌지 않았다**.

스트리머가 **금칙어**와 **허용어**를 직접 등록해서 위험 발언 감지 기준을 자기 방송에 맞춘다.
서버는 완료됐고 설정 화면만 남았다.

이건 **Spring REST API**다. AI 서버를 직접 부르지 않는다.

---

## 0. 두 사전이 하는 일

화면 문구를 쓰려면 둘의 차이를 알아야 한다. 이름은 비슷하지만 감지기에서 하는 일이 반대다.

| | 뜻 | 감지기에서 | 결과 |
|---|---|---|---|
| **금칙어** (`BLOCK`) | "내 방송에선 이것도 잡아줘" | 사전에 **추가** | 걸리면 즉시 경고 |
| **허용어** (`ALLOW`) | "내 방송에선 이건 괜찮아" | 사전에서 **제거** | 경고가 뜨지 않음 |

### 허용어는 같은 말의 변형까지 함께 빠진다

`씨발` 하나만 등록해도 `시발`·`ㅅㅂ`·`씨이이발`이 전부 안 걸린다. 기본 사전의 `씨발` 항목 하나에
변형 표기가 166개 붙어 있는데, 그걸 통째로 뺀다.

"변형도 따로 등록해야 하나요?"라는 질문이 나올 자리다. 안내 문구에 넣어 두면 좋다.

---

## 1. API

셋 다 **갱신된 전체 목록**을 돌려준다. 등록·삭제 후 다시 조회할 필요가 없다.
인증은 다른 `/streamers/me` 엔드포인트와 같은 Bearer JWT다.

```
GET    /api/v1/streamers/me/risk-terms
POST   /api/v1/streamers/me/risk-terms
DELETE /api/v1/streamers/me/risk-terms/{id}
```

### 공통 응답 (200 / 201)

```json
{
  "success": true,
  "data": {
    "block": [
      { "id": 12, "display": "개새기", "severity": "HIGH" }
    ],
    "allow": [
      { "id": 31, "display": "씨발" },
      { "id": 32, "display": "밤에 혼자 뭐 하세요" }
    ],
    "limits": { "maxPerKind": 200, "maxTermLength": 40 }
  }
}
```

| 필드 | 설명 |
|---|---|
| `display` | 사용자가 입력한 **원문**. 목록에 이 값을 그대로 보여준다 |
| `severity` | `LOW` \| `MEDIUM` \| `HIGH`. **금칙어에만** 있다 |
| `limits` | "12 / 200" 카운터와 입력창 `maxlength`에 쓴다 |

> **숫자를 화면에 하드코딩하지 말 것.** 상한이 바뀌면 `limits`만 따라가면 되도록 함께 내려보낸다.

서버는 매칭용으로 정규화한 표기를 따로 저장하지만 그건 응답에 넣지 않는다. 화면에 쓸 값은
`display` 하나뿐이다.

### POST — 등록

```json
{
  "kind": "BLOCK",
  "term": "개새기",
  "severity": "HIGH"
}
```

| 필드 | 필수 | 값 |
|---|---|---|
| `kind` | O | `BLOCK` \| `ALLOW` |
| `term` | O | 사용자 입력 원문 |
| `severity` | X | `LOW` \| `MEDIUM` \| `HIGH`. 생략하면 `MEDIUM` |

`201 Created` + 위 공통 응답.

**`severity`는 금칙어에만 노출한다.** 허용어는 감지를 없애는 쪽이라 등급이라는 개념이 없고,
실려 와도 서버가 버린다.

### DELETE — 삭제

`{id}`는 목록 응답의 항목 `id`다. `200 OK` + 위 공통 응답(삭제 후 남은 목록).

## 2. 입력 규칙

| 규칙 | 값 | 왜 |
|---|---|---|
| 최소 길이 | 2자 | 한 글자는 다른 단어에 묻혀 오탐만 낸다 |
| 최대 길이 | 40자 | 사전 매칭은 부분 문자열 탐색이라 긴 문장은 어차피 안 걸린다 |
| 종류당 개수 | 200개 | 금칙어·허용어 각각. 한쪽이 차도 다른 쪽은 등록된다 |
| 중복 | — | 같은 표현은 한 번만. 반대쪽 목록에 있어도 거절된다 |

### ⚠ 길이 판정을 클라이언트에서 재현하지 말 것

서버는 **정규화한 뒤** 길이를 잰다. 공백·문장부호를 지우고, 늘여쓰기와 3연속 반복을 줄인 결과가
기준이다.

```
"아!"        → "아"     1자  → 거절   (눈에는 2자)
"가" × 400   → "가가"   2자  → 통과   (눈에는 400자)
"씨 발!"     → "씨발"   2자  → 통과
```

입력창 `maxlength` 정도만 걸고, 나머지는 **서버 에러 메시지를 그대로 보여주는 편이 맞다.**
`error.message`는 사용자에게 바로 노출할 수 있게 쓰여 있다.

## 3. 에러

공통 에러 봉투를 쓴다.

```json
{
  "success": false,
  "error": { "code": "RISK_TERM_DUPLICATE", "message": "이미 등록된 표현입니다." }
}
```

| code | HTTP | 언제 |
|---|---|---|
| `RISK_TERM_TOO_SHORT` | 400 | 정규화 후 2자 미만 |
| `RISK_TERM_TOO_LONG` | 400 | 원문 또는 정규화 결과가 40자 초과 |
| `RISK_TERM_EMPTY` | 400 | 한글·영문·숫자가 하나도 없음 (`"!!!"`) |
| `RISK_TERM_DUPLICATE` | 409 | 같은 목록에 이미 있음 |
| `RISK_TERM_CONFLICTING_KIND` | 409 | 반대쪽 목록에 있음 — 먼저 지워야 함 |
| `RISK_TERM_LIMIT_EXCEEDED` | 400 | 해당 종류가 200개 참 |
| `RISK_TERM_NOT_FOUND` | 404 | 없는 `id`로 삭제 |
| `VALIDATION_ERROR` | 400 | `kind` 누락, `term` 공백 |

`CONFLICTING_KIND`는 "반대쪽 목록에 있습니다"로만 끝내면 사용자가 어디를 봐야 할지 모른다.
해당 항목으로 스크롤하거나 "허용어에서 삭제하고 등록" 버튼을 주면 좋다.

---

## 4. 언제 적용되나

**즉시다. 방송 중에 고쳐도 그 방송에 바로 반영된다.** 서버가 저장 직후 실행 중인 음성 세션에
새 사전을 밀어 넣는다.

> **"다음 방송부터 적용됩니다" 같은 안내를 넣지 말 것.** 설계 초안에는 그렇게 적혀 있었으나
> 실시간 반영으로 바뀌었다. 스트리머가 보조 모니터에 설정을 띄워두고 그때그때 고치는 사용을
> 전제한다.

---

## 5. 바뀌지 않는 것

- **음성 WebSocket 핸드셰이크** — 티켓 내부 형식이 바뀌었지만 프론트가 받는 것은 여전히 불투명한
  문자열이다. [FRONTEND_API.md](FRONTEND_API.md) 그대로다.
- **`alert` 이벤트 규격** — 필드가 그대로다. 금칙어에 걸린 경고도 기존 사전 경고와 똑같은
  모양(`source: "dictionary"`)으로 온다.
- **기존 감지 동작** — 사전을 등록하지 않은 스트리머는 지금과 완전히 동일하다.

---

## 6. 나중에 붙일 수 있는 것

이번 범위에서 뺐지만 **프론트 작업만으로** 추가 가능하다. 경고 카드에서 바로 등록하는 버튼이다.

```
⚠  "아 씨발 뭐야"                [ 이 표현 허용 ]  [ 무시 ]
```

`alert` 이벤트의 `hits[].matched`가 그대로 등록할 표기라 서버 변경이 필요 없다
([FRONTEND_API.md](FRONTEND_API.md) §4).

설정 화면을 열고 "내가 자주 쓰는 욕이 뭐였지"를 떠올리는 사람은 없다. 이 버튼이 실제 사용률을
좌우할 가능성이 높다.

다만 LLM이 문맥으로 잡은 경고(`source: "llm"`)에는 `hits`가 없다. 그때는 `text` 전체를 후보로
보여주고 사용자가 잘라내게 해야 한다.

---

## 7. 알려진 한계

허용어가 **기본 사전에 없던 표현**일 때는 동작이 확실하지 않다.

- `씨발`처럼 사전에 있는 단어 → automaton에서 빠지므로 **확실히** 안 걸린다.
- `"밤에 혼자 뭐 하세요"`처럼 AI가 문맥으로 판정하던 표현 → AI에게 "이건 봐줘"라고 알려주는
  방식이라 100%가 아니다. 준수율은 아직 측정 전이다.

실무상 스트리머가 등록할 것 대부분은 앞쪽이라 큰 문제는 아니지만, QA에서 "허용어 넣었는데 가끔
뜬다"는 리포트가 올라올 수 있어 미리 공유한다.
