## 3. 빌드·배포 절차

### 3-1. 서버 최초 세팅 (요약 — 상세는 DEPLOY.md §1~2)

```bash
# 1) 접속
ssh -i I15C204T.pem ubuntu@i15c204.p.ssafy.io

# 2) 저장소
git clone https://lab.ssafy.com/s15-webmobile1-sub1/S15P11C204.git ~/laive

# 3) 정적 디렉터리
sudo mkdir -p /var/www/laive/download /var/www/laive/web
sudo chown ubuntu:ubuntu /var/www/laive/download /var/www/laive/web

# 4) nginx
sudo cp ~/laive/deploy/nginx/laive.conf /etc/nginx/sites-available/laive
sudo ln -sf /etc/nginx/sites-available/laive /etc/nginx/sites-enabled/laive
sudo nginx -t && sudo systemctl reload nginx

# 5) .env 2개 배치 (§2 표대로 값 채움)
chmod 600 ~/laive/BackEnd/spring/laive/.env ~/laive/AI/.env
```

```bash
# 1) 백엔드 먼저 (laive_default 네트워크가 여기서 생성됨)
cd ~/laive/BackEnd/spring/laive

#   └ spring에 profiles:["app"]이 걸려 있어 서비스명을 직접 지정해야 뜬다

cd ~/laive/AI

# 3) 랜딩 (Jenkins 워크트리 밖 별도 디렉터리에서)
```

### 3-5. CI/CD (Jenkins)

- `laive-ci`: `dev` 브랜치 폴링 → Spring 테스트(`./gradlew clean test`) + AI 테스트(`uv run pytest`)
- `laive-cd`: `master` 폴링 → 동일 테스트 후 `Deploy Production` —
  제한된 SSH 계정(`deploy@`)으로 접속하면 강제 커맨드 `/usr/local/sbin/laive-deploy`만 실행됨
- 배포 스크립트(`deploy/jenkins/scripts/laive-deploy`): 워크트리가 dirty면 거부,
  spring·voice·chat-ai·collector 재빌드 후 헬스체크 실패 시 **이전 리비전으로 자동 롤백**
- 즉, **릴리스 = GitLab에서 dev → master MR 머지**. 서버 수동 배포 금지
  (Jenkins 관리 워크트리 `~/laive`가 dirty가 되면 이후 배포가 전부 거부됨)

## 4. 배포 시 특이사항

① **기동 순서**: 백엔드 compose → AI compose. AI의 `laive_default` 네트워크가
   `external: true`라 백엔드가 먼저 떠 있어야 한다 (`network laive_default not found`).

② **AI는 반드시 `docker compose -f compose.yaml up -d`**. `-f` 없이 띄우면
   `compose.override.yaml`(개발용, `restart: "no"`)이 합쳐져 죽어도 재시작하지 않는다.

③ **`OAUTH_ALLOWED_RETURN_URIS`는 CORS 허용 오리진의 원천이기도 하다.**
   설치 앱의 오리진 `laive://app/oauth/callback`이 빠지면 앱의 API 요청이 전부 403.
   이 문자열은 `src/main/index.ts`(RENDERER_SCHEME/HOST) · `FrontEnd/.env.production` ·
   서버 `.env` 세 곳에 함께 박혀 있으므로 바꿀 때 셋을 같이 고친다.

④ **방화벽(UFW)은 절대 건드리지 않는다** (SSAFY 서버는 접속 불가 시 초기화만 가능).
   도커는 iptables 규칙을 UFW보다 앞에 꽂아 우회하므로, 모든 compose `ports`는
   `127.0.0.1:` 접두사를 유지해야 한다. EC2 보안그룹이 1024~65535를 전부 허용 중이다.

⑤ **네이버·치지직·구글 개발자센터에 리디렉션 URI를 등록**해야 로그인이 동작한다.
   반영에 시간이 걸리므로 배포 전에 먼저 한다.

⑥ chat-ai 최초 기동은 감정 분류 모델(KcELECTRA ONNX, 641MB) 다운로드 때문에
   5~10분 걸린다 (`start_period: 300s`). named volume(`chatai-models`)에 남아
   재기동 시엔 재다운로드하지 않는다. 미리 굽기: `docker build --build-arg BAKE_MODEL=true`.

⑦ Windows에서 clone한 트리는 CRLF 문제로 `gradlew`·`entrypoint.sh`가 리눅스에서
   깨질 수 있다 — Dockerfile들이 빌드 시점에 `sed -i 's/\r$//'`로 방어한다.

⑧ DB 스키마는 Flyway가 기동 시 자동 적용한다
   (`BackEnd/spring/laive/src/main/resources/db/migration/V1__baseline_schema.sql` 외).
   TimescaleDB 확장은 `initdb/001-enable-timescaledb.sql`이 최초 초기화 때 생성.

⑨ 정적 웹 업로드 후 `chmod 755 /var/www/laive/web/assets` 필수(§3-4),
   nginx 설정 변경 후 `nginx -t` 통과 **후 reload까지** 해야 반영된다.

⑩ 자동 업데이트(electron-updater)는 미적용 — 새 버전 배포 시 사용자가 재설치해야 한다.
